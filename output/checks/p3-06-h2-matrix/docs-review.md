## 建议修正

1. `storefront-acceptance.md:63` 把“操作者与见证者”列为每项必填，容易新增必须有第二名真人在场的门。SPEC §9.1 要求经过培训的非开发人员实际操作，§9.0/ADR-012 要求单人日常发布，不要求额外真人见证。旧手册虽然也曾要求见证，不能据此把它当规范的不可取消条件。建议改为“记录操作者；如有见证者可记录”，用真实操作人确认、计时及可复核回执/前台证据证明完成。代理仍不能代签真人 PASS；正式内容双人复核属于 P7-02，不能混为本次日常操作前提。
2. `storefront-acceptance.md:57` 将“另验证历史恢复有效”写在 ≤3 分钟更换海报的完成条件内。SPEC §9.1 的三分钟是更换并预览；§9.0/ADR-012 要求历史恢复功能，但没有把两项串联后的总耗时限制为三分钟。建议明确“历史恢复是单独功能场景，不并入本次更换海报计时”，避免无意提高预算或让参与者不知何时结束计时。

可选的使用说明澄清：第45行可明确命令由环境准备人启动，等到 `MANAGEMENT_READY` 才交给操作人；第51行“退出清理”指停止该命令进程或运行期到期，单独关闭 Chrome 窗口不会立即结束其 `await stopped`。这些无需增加产品流程。

## 实际 preview 命令核对

- 根 `package.json:51` 转发到 API 包；`apps/api/package.json:46` 先构建依赖、运行两个 TEST 脚本测试，再执行 `management-center-local.mjs --serve`。手册未把命令包装成无需准备的生产管理入口。
- `management-center-local.mjs:70–116` 启动隔离 PG/S3 和管理运行时，先执行 `verifyManagementCenterBrowser` 并写自动 `validation.json`；`117–141` 才调用 `openManagementCenter` 并输出 ready，之后等停止信号。
- `management-center-open.mjs:26–66` 实际启动 `headless:false` 的 Chrome、一个 context/page、1440×900、`/zh-CN`；以内存 TEST 凭据设置安全 Cookie，并等待管理列表可见。没有执行真实 OIDC 登录。
- `management-center-local.mjs:52–56` 设置停止信号与 110 分钟上限；`runtime.json` 记录安全入口和 expiresAt。`storefront-acceptance-lifecycle.mjs` 逆序关闭所有 owned 资源，即使一项清理失败也继续其他项。
- 自动验收浏览器是独立 headless 流程；其已执行上传及生成对象不能计入随后真人计时。新手册对此作了明确区分。
