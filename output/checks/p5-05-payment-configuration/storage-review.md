## What the actual database cases establish

- Immutable managed drafts can remain incomplete without pretending to satisfy the old canonical publication requirements. Save, submit, approve, publish and rollback retain permanent idempotency receipts and exact authorization/audit associations. Same-key concurrency returns the same result; changed input conflicts; 256-character idempotency keys work.
- Enabled channels require approved current English lineage and all seven translations. Exact unchanged translations may inherit only the real three-event independent approval chain from a previously published managed source for the same account. Changed translation text, changed English, unpublished/no source and another account do not inherit. Copy proofs and all five new history tables reject mutation.
- Direct SQL rejects numeric strings, missing/unknown fields, invalid/null array elements, duplicates, excessive lengths and invalid JSON types. Extra canonical routes, extra country scopes and partially materialized scopes cannot commit against the immutable document. Validation, canonical routing, publication receipts and health activation remain linked by deferred database assertions.
- Publish and rollback compare the current head and validation facts. Changed deployed adapter facts invalidate confirmation. Two concurrent confirmations have exactly one winner. Every publication, including rollback, allocates a new health policy version and generation while retaining actual health; old probe leases are cleared. An unavailable old account cannot be re-enabled by rollback or recovered using its old lease.
- Revoked sessions and invalid CSRF fail. A session that expires while waiting on the actual publication mutex fails without a new receipt. A real head-row lock reaches the bounded transaction deadline, destroys the connection, and a subsequent read succeeds.
- The last two actual RED cases were `storage-uuid-red.log` (equivalent uppercase UUID returned `STALE_VERSION`) and `storage-capacity-red.log` (unpublished account history bypassed the directory limit). Final GREEN consumes root's normalization of UUIDs only in the new configuration contracts, and checks SAVE capacity against **all managed revision accounts + trusted deployment accounts + incoming accounts**, matching READ's retained history. Exceeding 100 fails explicitly before creating history; no account is silently discarded.

Earlier real RED/GREEN evidence includes `storage-copy-red.log` / `storage-copy-second.log`, `storage-document-red.log` / `storage-boundaries-first.log`, and `storage-deadline-red.log` / `storage-deadline-green.log`. It does not accept arbitrary response origins or relax command/session/attempt correlation. No non-owned source was edited by this reviewer.
