# P4-06 template/provider independent review

Reviewer: order_browser, neither reviewed module's implementation owner. Read-only scope: notification-provider `gateway.ts`, related gateway/TLS test coverage, notification contracts, i18n notification v1 renderer/layout/copy/identity/review/history, and Worker/Application profile selection boundaries. No source changes, shared build, or repeated heavy tests.

**Conclusion: ACCEPT for the local P4-06 candidate; no new actionable P1/P2 found.** The existing production template approval and external gateway acceptance gates remain necessary. This review does not approve the machine-assisted translations for production.

1. The HTTPS adapter copies/parses/freezes the flat profile, hashes that exact profile and exact command bytes, and validates receipt protocol, profile hash, request hash, notification UUID and idempotency key. It rejects redirects and unrelated receipts. UNKNOWN retries retain the same command; active/retained sender credentials are validated and captured at Worker startup, and a missing old transport fails closed.
2. One timeout spans credential resolution, fetch and streaming reads. The abort check after credential resolution prevents a late resolver from dispatching after that request timeout. Responses are restricted to JSON, at most 65,536 bytes, fatal UTF-8 decoding and a strict receipt schema; failures expose stable codes, not raw provider exceptions or content.
3. The separate absolute `dispatchNotAfter` is frozen into request bytes and therefore the request hash. An accepted receipt must predate it. A historical receipt accepted before cutoff may be replayed later; the receiving gateway must enforce the documented prohibition on new side effects after cutoff. This is a receiver protocol requirement, not a claim of provider-neutral exactly-once SMTP delivery.
4. Input/output schemas bound names, 500 historical items, subject/preheader and HTML/text. The versioned renderer displays ten items plus a localized remaining-item count while retaining the full total, limiting worst-case escaped content. No private message, fan display name or delivery address is accepted by the render variables.
5. Nonnegative safe-integer minor amounts are converted through BigInt quotient/remainder and ISO currency fraction digits, avoiding floating-point loss at the maximum safe integer. Ordering time is rendered in UTC/Gregorian form, independent of Worker timezone; no fulfillment timestamp is invented.
6. Every interpolated HTML text/attribute value is escaped; item locale attributes are enum-validated, URLs require an HTTPS fragment exchange path and the same order UUID, and substitutions are not recursively interpreted. Plain text preserves original names, with control characters rejected by the variable schema.
7. All seven locale catalogs cover the three events. Whole-message English incident fallback records the original requested locale and reason through the existing request path; historical render uses the saved identity independently of current incident configuration. Snapshot names keep their own language attributes and do not silently translate.
8. Event versions bind all locale copy, layouts, variable schema/refinements, summary policy and renderer version. Exact-hash reviews plus retained identity/content fixtures guard archived behavior. APPROVED requires all 21 matching human review records; current DRAFT records fail closed, including English fallback. New shipped behavior must add a version and retain the old renderer/runtime as documented.

Item 10 remains the root's running full check and previously collected provider/i18n/browser evidence; this review did not rerun or independently recertify those tests.
