# Independent transport-owner review of resource Application and source inspector

**Review conclusion: ACCEPT for the implemented local checkpoint scope.** The final real HTTP/S3/browser run passed 1798 assertions across 159 requests (`http-final.log`). Overall checkpoint acceptance remains subject to root's complete repository checks.

Reviewer authored only the new resource HTTP route/tests and local HTTP/S3/browser harness. The reviewed Application, source inspector, shared contracts/ports, TEST composition and PostgreSQL code were written by other owners. This is a non-author code review, distinct from the transport owner's self-check.

## Reviewed boundaries

- `packages/application/src/resource-management.ts`, `resource-management-upload.ts`, `resource-management-shared.ts`, and `resource-management-idempotency.ts`: all commands use current canonical session/MFA/permission authorization, including replay. Separate token digest purposes preserve the established admin authentication boundary. Caller fields cannot supply trusted IDs, object keys, dimensions, audit identity or decoded receipts. Command hashing retains exact input values and stores only typed result references.
- BEGIN commits a bounded immutable reservation before signing. Returned storage descriptors bind the server-generated SOURCE identity, checksum, bytes, MIME and expiry; the external projection contains only method, URL, headers and expiry. The code remains provider-neutral. COMPLETE reads canonical ticket identity, performs network inspection outside the transaction, then independently reauthorizes and locks/rechecks the ticket before atomic registration and idempotency completion. Completed exact-key replay avoids inspection.
- `packages/media-image/src/source-inspection.ts`, `image-pipeline.ts`, `storage-transfer.ts`, and existing `failure.ts`: source identity is checked by HEAD and bounded streaming GET, including actual length/checksum/MIME. Redirects are rejected. Header metadata is followed by complete pixel decoding with byte/pixel/dimension/frame limits, strict codec warnings, orientation verification and bounded request/codec budgets. Only fixed failure categories leave the adapter. Source inspection does not create a processed image or approve rights. The processing path still strips source metadata.
- `packages/contracts/src/resource-management.ts`, `resource-management-openapi.ts`, the new persistence/media port types, `apps/api/src/resource-management-composition.ts` and bootstrap integration: ten additive routes agree on body/header authority and private response policy. TEST composition validates configuration, borrows media ports, and owns its PostgreSQL lifecycle once. No production administrator login or route activation is introduced.
- The actual PostgreSQL `mediaProvenanceEligibilitySql` expression was exercised against the real worker-created master: current approved original permits eligibility, HTTP rights revocation denies it, and restoration permits it again. Existing publication state remained unchanged. This proves the current eligibility expression, not a completed future publication or cache-invalidation rollout.

## Confirmed issues closed during integration

1. A valid 45-second session-clamped upload was rejected by the legacy S3 upload minimum of 60 seconds. The real HTTP RED includes exact `INVALID_COMMAND` at the storage boundary. Root changed only upload minimum to one second and pinned the signing instant. The harness checks both returned expiry and the actual S3 signature deadline against the six-digit session expiry.
2. Internal source GET grants used `now + 60s`, while the S3 download adapter required at least 60 whole remaining seconds. A one-millisecond adapter-boundary advance could therefore produce `STORAGE_UNAVAILABLE`. The inspector owner reproduced this with the real S3 boundary and changed only internal GET validity to 120 seconds. The download minimum, external upload/session limits and codec/request budgets remain unchanged. Evidence: `source-inspection-download-window-red.log` and `source-inspection-download-window-green.log` (six assertions).
3. After PostgreSQL tightened historical permission checks, the expired-ticket fixture's audit time preceded its freshly created resource role grant. The database correctly rejected it with SQLSTATE 23514 and the fixed `RESOURCE_PERMISSION_HISTORY` category. The fixture now requests a consistent explicit historical resource permission/role/grant timestamp; production guards are unchanged.

No additional confirmed blocking Application or inspector defect was found in the reviewed implementation. Source-owned behavior is bounded to synthetic local TEST composition. Production login, actual operator uploads, publication/rollback and audited cleanup of unreferenced private uploads remain separate work.
