## Performance interpretation

The fixed matrix is seven canonical locales, three page kinds (home/artist/gift), and three mobile Lighthouse attempts per kind: 63 raw reports, forming 21 aggregates. Resource-byte sampling separately covers six page kinds, seven locales and two viewports: 84 pages. Every successful Lighthouse attempt writes raw JSON and available HTML before aggregation; runtime-error attempts are retained and fail. Completed numeric budget failures retain the whole collected matrix with `COLLECTED_BUDGET_FAILED`; the code never selects the best run or describes a failed callback as success.

The budget verdict is **all 21 three-run medians** meeting score >=0.90, LCP <2500ms and CLS <0.1, with min/median/max retained. It is not a claim that each of the 63 individual scores or timings meets the threshold. The JS <150,000 gzip-byte recommendation and per-image <600,000 hero/<400,000 regular-image SHOULD values are explicit separate recommendations; they are not hidden in the laboratory score verdict. Resource bytes come from actual initial navigation responses through network idle/fonts readiness before scrolling/eager mutations. JS is recompressed with Node gzip for a comparable byte budget, explicitly distinct from actual wire encoding.

Resource pages use a fresh isolated browser context and CDP cache disabling. For Lighthouse, the installed **13.4.1** source was inspected: `core/config/constants.js` defaults `disableStorageReset: false`; `core/gather/driver/prepare.js` resets URL storage; `core/gather/driver/storage.js` clears disk cache and toggles cache disabling to evict memory. The harness does not override storage reset and preserves actual settings/warnings per raw report. This supports a requested cold browser run, subject to the actual raw run warnings. The same compiled TEST server and potentially warm image optimizer are explicitly disclosed; this is not a full cold server/origin/CDN benchmark, RUM, field INP or physical-device evidence.

## Concurrency, visibility timing and cleanup

Concurrent read rounds issue homepage, directory and SEO reads together under three varied orders/delays for all seven locales. Each group's complete results are saved before status/strict-schema assertions; a failed group stops the run and is never retried. Actual database deadlock counts are additionally compared. This checks public read/read behavior and does not claim general arbitrary-write deadlock freedom.

Visibility performs normal source read/COPY, seven-language review, preflight/validate/publish and normal rollback. The measured clock starts after each actual publish/rollback response is acknowledged, not before authoring or review. Each probe's entire API/Chrome document/root XML/locale XML/shard work counts toward the same sixty-second budget; stale/error observations remain in order, and work finishing after the limit cannot pass. The final artist names and publication IDs/timestamps must match in all seven locales. Cleanup rollback runs if the changed publication remains active after failure. The scope is local TEST zero-TTL origin revalidation, explicitly not external CDN purge SLA evidence.

Owned resources close in reverse registration order; a close failure does not skip remaining closes, and original plus cleanup failures propagate. The independent lifecycle tests use actual short-lived loopback listeners and confirm unrelated listeners remain open. The outer harness writes each browser attempt to its own directory and retains failure JSON; successful protocol/callback labels are explicitly narrower than overall P3-06 acceptance.
