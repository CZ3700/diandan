# 管理中心：支付设置

本页说明 P5-05 的操作与恢复方式。当前使用本地 OIDC 和 TEST 支付环境；统一、可重启保留数据的完整体验入口以 `local-experience-readiness.md` 为准。

## 日常调整

1. 在管理中心进入「支付设置」，选择「编辑副本」。系统保存新版本，保留原来的发布历史。
2. 从已接入账户中选择渠道，调整是否允许新付款、展示顺序、开放比例及适用范围。国家、市场和币种需要明确填写，不会根据语言自动改变。「高级：渠道健康设置」可沿用现有值；界面缺少现有值时须完整填写后再保存。
3. 填写面向粉丝的渠道名称与支付提示，保存草稿。新文案或修改后的文案需要另一位具备相应语言权限的人员审核，包括英文。仅调整规则时，同一账户已发布版本中完全未改动的文案可沿用原审核证据。
4. 选择「检查发布变更」，处理提示的问题，核对「变更前／变更后」。确认原因并勾选确认项后发布。缺少发布权限的编辑者只能保存和检查。

规则金额以最小货币单位输入，并显示实际金额预览；同一条规则列出的每种币种共用所填整数限制，额度不同应分开设置。开放比例使用百分比。要暂停所有新流量，可以保留有效规则并将开放比例改为 0%；空路由不能发布。

## 恢复旧配置

在「版本历史」选择曾发布、当前未启用的版本，检查恢复差异后确认「恢复此版本」。系统生成新的发布记录和健康策略版本，不改写旧记录。旧账户或文案不再满足当前条件时，检查会拒绝恢复，需先修正原因。

正常数据库可用时，各实例默认每 10 秒同步配置；验收要求发布和恢复均在 60 秒内生效。本地双进程验收将轮询设为 1 秒，报告中的传播耗时只对应这个 TEST 设置。数据库暂时不可用时保留上一份完整配置，恢复后继续同步。

既有付款、退款及结果待确认的交易继续使用原账户与原请求记录；配置变更不会重新收费。

## 中断后的操作

若提交后断网或提示结果尚未确认，使用「恢复本次请求」。同一浏览器标签页刷新后仍保留原请求，恢复时使用相同的幂等键。先处理这个请求，再做其他变更；不要另建相同发布请求来猜测结果。

若提示当前版本已改变，刷新后重新检查差异。若没有已接入账户，由部署人员初始化实际已部署的适配器和不可变账户配置。本页不会上传支付代码，也不会显示或编辑密钥、银行卡资料及钱包凭据。

## 开发验证入口

- `pnpm --filter @fan-support/api test:postgres:admin-payment-configuration`：真实 PostgreSQL、TLS TEST PSP、两个独立 API 进程及发布恢复协议。
- `pnpm --filter @fan-support/api test:browser:admin-payment-configuration`：上述协议及七语言桌面／手机尺寸管理界面。
- 原生隔离 PostgreSQL 运行时可通过 `ADMIN_PAYMENT_CONFIG_TEST_POSTGRES_BIN` 指定已安装二进制目录；不接受用户已有数据库目录，不操作生产数据。

正式商户 sandbox、真实小额支付、正式身份与关键译文批准、staging 及生产发布仍遵守原阶段验收条件。
