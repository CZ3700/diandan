# PSP 接入验收证据模板

复制到当次接入的独立证据目录填写。空白、未执行和模拟结果均不等于 GO；没有真实身份/资金/部署授权时，保留相应门未执行，继续完成已授权本地范围。操作步骤见[新增 PSP 手册](psp-onboarding.md)。

## 1. 运行身份与范围

| 字段 | 本次值 |
| --- | --- |
| Task / 接入记录 ID / 时间与时区 | 待填 |
| 技术 owner / 独立 reviewer | 待填 |
| 业务/法务 / 财务 / 运维 owner | 待填 |
| commit / dirty 状态 / 源文件 manifest hash | 待填 |
| Node / pnpm / PostgreSQL / SDK/API 版本 | 待填 |
| adapter key / version / protocol | 待填 |
| 账户及环境的安全引用 | 待填；不填密钥或真实商户私密资料 |
| TEST fixture / 真实 PSP sandbox / 真实资金 / staging / production | 逐项明确；不得仅写“测试通过” |
| 镜像 digest / 环境配置批准引用 | 待填或未执行 |
| 官方文档 URL / 核验日期 / 账户能力批准引用 | 待填 |
| 已授权执行范围与当次授权引用 | 待填 |
| 本次未执行范围及唯一进入条件 | 待填 |

| 国家/市场/币种/方式/金额/设备能力矩阵 | 待填 | 待填 | 待填 | 未执行 |
| 结算/费用/准备金/退款/拒付/对账 | 待填 | 待填 | 待填 | 未执行 |

## 3. 技术验收

按实际执行填写结果，保留初次失败和修复后新运行。报告中数量需注明“测试用例/断言/任务图/请求/截图”口径，不将它们混算。

| 检查 | 命令/运行 ID | 退出码、范围与数量 | 原件路径及 hash | 结论 |
| --- | --- | --- | --- | --- |
| fake 正式七操作 shared conformance | 待填 | 待填 | 待填 | 未执行 |
| 新 adapter shared conformance（若有） | 待填 | 待填 | 待填 | 未执行或不适用 |
| TLS gateway 正式套件/错误关联/退款重放漂移/同键冲突/超额/证据复用负例 | 待填 | 待填 | 待填 | 未执行 |
| endpoint-scoped 正式 verifier/坏签名/错账户环境/过期与轮换 | 待填 | 待填 | 待填 | 未执行 |
| 原文加密 durable inbox/事务失败 ACK/重复乱序早到迟到 | 待填 | 待填 | 待填 | 未执行 |
| 实际 PG 灰度/双 API 发布和回退/UNKNOWN 原账户恢复 | 待填 | 待填 | 待填 | 未执行 |
| 新 adapter 的账户/环境资格、身份不可变与持久准入对抗检查 | 待填 | 待填 | 待填 | 未执行或不适用及原因 |
| 健康熔断/只读探测/失效租约或代际 | 待填 | 待填 | 待填 | 未执行 |
| 全额/部分退款、取消、UNKNOWN 占用及可信对账 | 待填 | 待填 | 待填 | 未执行 |
| webhook/死信/通知异常恢复与重复副作用计数 | 待填 | 待填 | 待填 | 未执行 |
| 七语言、键盘、错误、reduced motion、双视口（变更时必需） | 待填 | 待填 | 待填 | 未执行或不适用及原因 |

## 4. 灰度逐级记录

每个发布重复填写一份；配置发布通常有新规则行 UUID，不能以同一 ruleKey 声称 cohort 不变。

| 字段 | 本阶段值 |
| --- | --- |
| 阶段：disabled / internal / 5% / 25% / 100% / stop / rollback | 待填 |
| 实际环境与内部隔离证据 | 待填；INTERNAL+TEST 不证明 LIVE 员工过滤 |
| 账户 ID 安全引用 / 账户状态 / merchant 状态 | 待填 |
| config revision / publication ID / 前版本 | 待填 |
| ruleKey / 实际 routeRuleId / 算法版本 | 待填 |
| 账户 basis points / 规则 basis points / 理论交集 | 待填；两个 500 约 0.25%，不是 5% |
| 允许国家/市场/币种/方式/金额/设备 | 待填 |
| 关键文案 revision / 审核或继承证据 | 待填 |
| health policy revision / 观察阈值 | 待填 |
| 权限/MFA/原因/确认/幂等回执与审计引用 | 待填；不包含 token 或原请求私密字段 |
| 发布提交时刻 / 每个实例读取和生效时刻 / 最大传播耗时 | 待填；注明实际轮询间隔和独立进程 |
| 稳定桶样本与七语言/同 session 重试/两节点对照 | 待填；客户端不得指定 seed |
| 观察开始/结束 / 预先批准最少样本 / 实际分母 | 待填 |
| 成功率/技术错误/取消拒绝/UNKNOWN 年龄/退款未决 | 待填 |
| webhook backlog/延迟/死信/通知失败/告警 | 待填 |
| 停止/回退前后 create/refund/effect/fulfillment/notification 计数 | 待填 |
| 旧 UNKNOWN 原账户/环境/键/attempt/receipt 保持证据 | 待填 |
| 本阶段 GO/NO-GO、财务/运维/发布签署、下一步 | 未执行 |

样本不足或观察窗口未完成时保持本阶段。资金错配、重复副作用、证据不可信时立即 NO-GO；停止新付款后仍保留原 webhook/查询/退款/恢复路径。数据库不可用时的入口级停止措施需独立证据，不能把发布失败写成停用成功。

## 5. sandbox 与真实小额分开填写

| 验收 | 真实 PSP sandbox | 真实小额支付/退款 |
| --- | --- | --- |
| 商户/环境/方式/币种组合 | 未执行 | 未执行 |
| 当次授权/限额/笔数/手续费预算 | 未执行 | 未执行 |
| 前台→托管认证→只读回跳→可信入账→安全查单 | 未执行 | 未执行 |
| 平台冻结金额/币种与 PSP capture 一致 | 未执行 | 未执行 |
| webhook receipt 或认证 reconcile 审计引用 | 未执行 | 未执行 |
| 全额/部分退款/原交易引用/退款完成证据 | 未执行 | 未执行 |
| 资金对账、费用/结算/退款到账状态 | 未执行 | 未执行 |
| pending/UNKNOWN/差异及处置 owner | 未执行 | 未执行 |
| 财务与独立技术复核/日期/GO | 未执行 | 未执行 |

真实卡号/CVV/钱包授权仅进 PSP 托管界面；真实身份、账单和商户材料保存于批准的受控库。此表只放非敏感引用与摘要，不粘贴截图原文或支付 payload。每种首发方式分别列行，不能用一次 TEST 付款代表全部网络/币种。

## 6. 不可变证据与结论

| 字段 | 本次值 |
| --- | --- |
| 初次失败/诊断/修复后运行的各自原件 | 待填 |
| 证据 manifest、文件 hash、访问控制与保留责任人 | 待填 |
| 无 secret/PII/raw payload 的检查命令及结果 | 待填 |
| 本轮创建的临时资源与清理结果 | 待填 |
| 平台永久 receipt/audit/publication 引用 | 待填；不删除或重写历史 |
| 本地门 / sandbox 门 / 小额门 / 发布门各自结论 | 均未执行，逐项更新 |
| 未完成事项、owner、具体解除条件 | 待填 |
| reviewer 签署、复核源版本与日期 | 待填 |

新结果以新目录/运行 ID 追加，不覆盖失败记录。hash 用于完整性校验，不自动证明财务真实性或审批。永久业务回执与短期加密 webhook 原文的保留义务分开：原文仍按自身 TTL 删除，不能借归档无限期保留。只有实际满足对应门才能写 GO；本地通过不推导生产发布。
