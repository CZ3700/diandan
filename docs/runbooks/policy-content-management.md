# 政策内容管理

从管理中心的「页面管理」进入「政策条款」，维护 Delivery、Privacy、Refunds、Terms 四类政策。同一区域的「信息页面」标签管理关于我们、FAQ、客服信息。两个标签共享后台入口，保留各自内容、修订与发布接口，不复制数据或改写历史订单接受的政策版本。

入口和标签仅显示当前账号有权访问的内容。切换标签时，未保存编辑会提示确认；取消后仍留在原编辑器。处理中暂时不能切换。已进入页面管理时，再次点击侧栏入口保留当前标签。

## 权限与入口

- `content.read` 可进入政策工作区，只读取账号已获授权的语言。
- `content.edit` 可保存正文；英文原文及共同结构的修改仍受后端语言范围检查。
- `content.policy.manage` 可登记政策标识与类型。已有政策应选择原标识编辑，避免重复登记。
- `content.translation.review` 可审核获授权语言。正文编辑者和结构编辑者不能批准自己的修订。
- `content.publish` 配合全部七语言权限可执行发布及恢复。服务端再次校验每个操作。

## 编辑与同步

1. 选择政策和内容语言，修改标题、摘要、正文。标题最多 160、摘要最多 300、正文最多 20,000 字符。
2. 正文只支持 `p`、`br`、`strong`、`em`、`ul`、`ol`、`li`。不接受属性、脚本、图片或链接；右侧预览采用同一格式限制。
3. 保存产生新的不可变修订。英文变化会令未更新的译文过期，不能沿用旧批准记录。字面无需修改的译文也必须明确更新其英文来源后重新审核。
4. 每份政策包含 `en / zh-CN / th / vi / ja / es / pt` 七种语言。语言面板显示缺失、草稿、审核中、已批准、过期或无权限状态。
5. 修改共同生效时间时，选择晚于新修订保存的 UTC 时间。到达生效时间且审核完成后手动发布；填写时间本身不创建自动发布任务。

未保存内容受页面内导航、界面语言切换、退出及关闭页面保护。网络错误不代表保存失败；先按提示重试或重新读取，避免重复建立修订。

## 七语言内容包

JSON 内容包只填入编辑器草稿，应用后仍需保存和审核。每个文档必须包含完整七种不同语言；不接受审批记录或自行声明的审核回执。

```json
{
  "schemaVersion": 1,
  "documents": [
    {
      "kind": "DELIVERY",
      "translations": [
        {
          "locale": "en",
          "origin": "MACHINE",
          "fields": {
            "title": "Delivery",
            "summary": "Delivery information.",
            "body": "<p>Policy text.</p>"
          }
        }
      ]
    }
  ]
}
```

上例仅展示字段结构，导入时必须补齐其他六语言。`kind` 为 `DELIVERY / PRIVACY / REFUND / TERMS`，来源为 `MACHINE` 或 `HUMAN`。AI 生成或翻译的内容使用 `MACHINE`；载入内容包不会把来源自动改为人工。

## 审核、发布与恢复

编辑者逐语言提交审核；另一位有对应权限的审校人对照英文核对后批准。英文也需要审核。发布前执行预检和验证；缺译文、过期、未批准或生效时间不满足条件时，按预检结果修正。

发布以一份政策的完整七语言修订为单位，不能只发布某一种语言。历史记录提供旧修订选择、恢复预检及发布状态；恢复不会覆盖历史修订。当前订单继续保留下单时接受的政策版本。

发布成功与缓存刷新完成分开展示。缓存任务失败时，可从发布状态重试；不要用再次编辑政策代替失败任务重试。

## 验证入口

运行 `pnpm --filter @fan-support/admin test`、`pnpm check:dev`，并在独立本地 TEST 资源上核对保存、英文来源过期、独立审核、整组发布、历史恢复与错误重试。管理界面覆盖 390×844 和 1440×900 的七语言布局。公共 TEST、正式 staging 和生产部署分别记录验收证据。
