# 管理中心订单操作

本入口属于 P5-02 本地开发范围。生产身份服务、正式邮件服务、真实商户和上线环境验收仍按总进度门禁执行。

## 日常处理

1. 登录管理中心，进入「订单」。订单运营人员默认进入订单页；有内容管理权限的人员仍可使用艺人、礼物、海报入口。
2. 搜索订单号、艺人或礼物，或用处理状态与审核状态筛选；超过一页可翻页。
3. 打开订单，逐件确认礼物和收礼艺人。名称、图片、价格、语言与库存方式采用下单时的历史记录。
4. 有留言或署名时，选择自己获授权的审核语言，点击「打开私密留言」，阅读并确认理解其语言后批准或拒绝。未审核或被拒绝的内容不能进入准备、送达流程。未知语言和与所选语言不一致的内容需要具备分流权限的人员处理，不会自动批准。
5. 点击「开始准备」，转交完成后点击「标记送达」。多件礼物分别处理，最后一件完成才把整单标记为已送达。
6. 内部备注按需打开、提交；离开面板即清除浏览器中的内容。普通列表和订单详情只显示备注数量，不显示正文。
7. 如粉丝未收到通知，确认当前状态后点击「重发最新状态通知」。系统生成独立发送记录，保留原历史；页面显示已加入队列不代表粉丝邮箱已经收到。

虚拟礼物、按单准备或预售礼物可以按其既有销售规则重复购买。运营准备和送达不再次扣减库存；有限库存仍由支付确认链路处理，不可通过后台状态按钮绕开。

## 异常操作

- 经理可以展开额外操作，选原因并确认暂停或恢复。恢复只回到本入口暂停前的合法状态。
- 支付待复核、库存不足造成的暂停、争议及不允许的状态不能在此强制恢复。该入口不改变付款结果，也不提供退款或财务调账。
- 遇到「订单已更新」，刷新后重新核对。网络中断后的重试保留原操作键，避免重复审核、备注或发送。
- 无权限、退出登录、访问过期或留言内容版本变化时，重新登录或重新打开相应内容；之前读取的私密内容不会随旧响应重新显示。

## 通知结果不确定

重发结果为 UNKNOWN 时，系统保留同一次发送的恢复记录，不允许换新操作键绕过不确定结果。

已有 UNKNOWN 且尚未确认成功的历史记录会继续阻止人工重发，即使后续自动状态通知已经送达。这是当前保守策略；本阶段没有人工清除 UNKNOWN 的入口。不要修改数据库、删除发送记录或换键强行发送，应保留记录进入后续通知调查/对账工作。

旧发送的固定接收截止时间到达前，后续自动状态通知也会等待；截止后可以继续发送新状态。该规则约束平台向接收服务的提交顺序，不能保证外部邮箱最终展示的到达顺序。运行维护循环每次分别扫描自动和重发队列各 `limit` 条，总扫描上限为 `2 × limit`。

## 本地验证入口

在仓库根目录使用 Node 24.20.0 与 pnpm 11.25.0：

```sh
pnpm check:dev
pnpm check:contracts
pnpm --filter @fan-support/persistence-postgres test:postgres:admin-orders
pnpm --filter @fan-support/persistence-postgres test:postgres:admin-order-resends
pnpm --filter @fan-support/api test:postgres:admin-orders
pnpm verify:admin-orders:browser
pnpm --filter @fan-support/persistence-postgres test:postgres:notifications
```

这些验证创建自有 PostgreSQL、TLS 对象存储、签名测试支付与本地 OIDC 环境；不会发出真实邮件或真实扣款。浏览器只保存非私密面板截图，不保存 HAR、trace、原始请求头或私密正文。

本阶段证据目录：`output/checks/p5-02-order-operations/`；任务状态和正式退出结论以 `docs/progress/phase-5-operations-payments.md` 为准。
