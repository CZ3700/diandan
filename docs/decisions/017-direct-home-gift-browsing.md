# ADR-017 — 首页直接浏览礼物

- 状态：ACCEPTED（2026-09-24 用户明确要求）
- 原因：首页艺人下仅有手工推荐位，而完整礼物目录要求先选择地区，增加无必要浏览步骤。

## 决定

首页在艺人展示后直接呈现已发布礼物的图片、名称、简介、分类与分页，运营上架即自动纳入，无须另外选择推荐位。`/gifts` 的无市场入口复用相同内容目录；选定有效市场/币种后的原价格目录保持。

新增独立 `GiftBrowseQuery/Response` 和 `GET /api/v1/gift-browse`，通过 Application → ContentReadTransaction → CatalogDirectoryRepository 从真实发布快照分页。所有公开内容沿用已有 publication/translation/media 证明；日常原文发布和严格英文事故 fallback 边界保持。目录不返回 offer，也不选择或修改 market/currency/cart。查询有 page/pageSize 上限、category 与可选 idol 约束，不向前台下载全部商品。

首页沿用已确认黑金风格及图片 contain 规则，分页/筛选可用键盘操作、URL 可恢复。详情先展示内容，涉及价格、资格与购买时才要求地区/币种确认。支付及已存在的交易保持原状态机与权威。

## 验证与回退

P6-02 本地范围内先失败测试，受影响合同/PG/API/前台测试，再真实七语双端与320px/200%缩放验证。失败、空目录、异常页号和地区接口不可用均须有可恢复状态。浏览不得创建购物车、选择默认市场或从语言推导货币。

这是兼容新增只读接口，不改旧合同、不迁移数据。若需回退前台，恢复前一已验证版本；保留新增只读接口可兼容调用，不回滚用户内容或订单。正式人工可访问性/语言、商户、云与发布门仍保持。

## 增补：唯一市场直显价格（2026-09-26，V2 方案 §4-2，规范 4.0.0 §0.2 第 4 项）

本条修订"浏览不得……选择默认市场"：

- **适用条件**：已发布的市场只有一个，且该市场只有一个币种（以 `GET /api/v1/storefront-context` 为准）。此时没有可选项，这对市场/币种就是作用域。只要有第二个市场或币种，或者上下文不可用，就恢复显式选择。
- **不变的原则**：
  - 仍不从语言推导币种；
  - 浏览不创建购物车；
  - 显式选择（包括无效值）永远优先；
  - 价格仍来自该市场的真实已发布价目，加入购物车与结账仍由服务端重验，所以不会虚构报价。
- **流式不变**：
  - 礼物详情先流式输出内容。等上下文确认只有一个市场后，价格与加购面板在原本市场选择的位置流入；读价格失败时回退为市场选择。
  - 艺人页礼物目录原本就在 Suspense 内等待上下文，唯一市场时直接显示价格。
- **第二阶段**（随方案 §4 第 3 项首页改版一并处理，并补浏览器验证）：
  - `/gifts` 与首页的无作用域目录带价；
  - 规范 URL 去掉隐含作用域；
  - 页眉/页脚隐藏"选择地区"入口。

  这些位置目前不等待上下文、先行渲染；要改它们，需要先调整流式结构。
