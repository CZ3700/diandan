# ADR-011：礼物类型、销售库存策略与工作室交付

> 状态：Accepted for implementation — 用户明确补充需求，P3-03
> 日期：2026-09-07
> Owner：Codex `/root`
> 关联：规范 9.3、P3-03、R-06/R-10/R-13/R-17

## 决定

虚拟、实体、心愿、周边、其他是礼物的展示与运营分类；鲜花、食品等是内容品类；限量现货、按单准备采购、预售是规格级销售策略。三者分别存储，不互相推导。付款后仍由工作室准备并转交艺人。

按单准备采购允许没有现货库存记录，可重复售卖；它必须继续通过真实发布、价格、适用艺人和可售状态检查。限量库存使用实际余额与预占，不伪造无限数量。库存流水只能追加，运营不得覆盖 reserved。交易已引用的库存策略必须保护历史支付与预占解释，必要时创建新规格。

礼物类型进入与 gift revision 一对一的不可变 profile。新发布的 sidecar 证明绑定具体 publication、revision、profile 与原 manifest hash，复用现有审核、发布、head、outbox 和 purge 事务。旧 344 个合同 root、已有内容和发布 hash 保持不变。普通复制和翻译导入也要继承 profile；新受管内容缺失 profile 不能降级为旧内容。旧 revision 没有分类时仅在明确 legacy 路径展示未分类。

价格从当前市场与币种的整簿版本复制，追加改价记录与发布头；发布回退追加事件，不能通过改写历史状态让旧价格重新“变新”。管理权限分为礼物、价格、库存；每次命令和幂等重放都检查当前会话/MFA/CSRF/RBAC，旧内容权限和会话合同不扩枚举。

## 验证与边界

测试覆盖无库存重复可售、限量零库存与并发保护、暂停恢复、策略切换、不可变调价与回退、七语言和独立详情审核、授权撤销及审计失败回滚。新增管理 UI 以实际 PostgreSQL/API/S3 和七语言双视口浏览器验收。

本轮证明管理和目录可售结果，不把重复读取报价描述为多笔真实付款。真实 PSP、订单流程和履约执行仍按后续阶段验证。不得从本需求推导众筹、余额、自动送达或寄送粉丝的新业务。
