# ADR-020：可配置装修与完整交易优先上线

- 状态：Accepted
- 日期：2026-09-28
- 用户依据：用户接受“可配置主题装修＋完整收费运营”的建议，并明确要求“立刻采纳……梳理规划然后逐步推进”。

## 决定

1. 复用现有自研商城、管理中心、PostgreSQL 和支付适配边界；首发增加面向运营的装修功能，不迁移到 Shopify，不重写商城核心。
2. 装修以已部署的页面模块、布局变体、主题参数和动效预设为边界。首页、艺人页、礼物页及导航/页脚可以调整；交易页面支持统一视觉与辅助展示，金额、归属、权限和付款状态不成为装修参数。任意画布、任意脚本和通用建站平台不属于首发。
3. 保留简单内容上传、黑金默认风格、七语言、四类礼物、独立库存策略、私密留言与既有订单能力。管理中心按内容、装修、订单组织日常操作，高级设置折叠；不把日常换图变回多阶段审核。
4. 首发只要求一家实际获准的 PSP 完成本站沙盒和真实小额付款/退款闭环。已有 Stripe/Airwallex 代码保留；其余渠道、PayPal、USDT 实接、多渠道切换不作为本次上线前置。Stripe 是当前首个工程验证候选，不代表已选定或获批的生产商户。
5. 支付、邮件、身份和正式运行环境的准备从现在与装修并行，替代 2026-09-26“外部接入留到最后”的排序。账号或审批缺失时明确登记，继续不依赖它们的工作，不能用 TEST 替代实际验收。
6. 首发采用可重复的正式构建/部署、基础健康与队列/通知告警、加密备份及一次实际恢复/版本回退演练。完整云平台迁移、全量 OTel/分析看板、多通道自动路由与精确 CDN purge 平台可后移；若启用公共缓存，仍须证明发布时效及语言隔离。正式生产位置和资源选择仍需实际决定，不能默认把现有远程 TEST 原地转正。
7. 不删除旧测试或放宽资金、隐私、权限不变量。既有失败按实际影响修复或解释；没有证据的能力不得改标完成。上线由经营、购买、履约和故障恢复四类实际验收决定。

## 兼容与后果

- SPEC 升为 5.0.0；本 ADR 优先于旧 §9.4 的禁止装修条款、V2 多 PSP 首发目标及外部接入后置安排。旧证据与未验收事项保留。
- 排序/显隐属于非语言布局元数据，不能靠改旧已冻结内容合同或伪造七语审校实现。布局与内容更新必须互不覆盖；旧页面无装修配置时保持原样。
- 首个样板必须贯通真实页面预览、数据库草稿、发布与恢复；仅做编辑器外观或 localStorage 演示不算完成。
- 4–6 周仅为资源及时、范围稳定时的工程粗估；账号审批等待不包含在内，首次样板和真实沙盒联调后重新估算。
- 当前授权涵盖规划、开发与本地/隔离测试；不新增真实资金、对外正式发布、购买云资源或迁移现有服务器数据的授权。

实施与完成标准见 [当前上线计划](../plan/2026-09-28-flexible-storefront-launch.md)，状态只记入 [当前进度](../progress/launch-progress.md)。

## 2026-10-01 增补：站点品牌标识

用户要求从店铺装修上传或替换站点 Logo。新增独立 `StorefrontBrand`，分别引用浅色、深色主题的 Logo 资产；沿用权限、草稿、预览、发布和追加恢复，不把品牌资产塞入旧主题 JSON 或改变既有主题历史。只控制商城共用页头、页脚，对应图片缺失或失败时使用配置站点名。

Logo 复用受权原图上传票据与存储 port，采用独立、限额的静态透明图处理器；完整解码、清除元数据、保留 alpha/比例且不放大，公开衍生图为 WebP。专属不可变 Logo 资产记录绑定原上传、校验和、版权引用及操作者审计，PostgreSQL 保持引用与发布事实的唯一来源；已有商品/海报加工 profile 及 `media_assets` 记录不改写。此设置不包含 favicon、邮件、支付或凭证品牌替换，也不自动批准某一设计提案作为正式品牌。
