# ADR-019：虚拟礼物的交付语义 = 数字应援凭证（方案 A）

> 状态：Accepted（2026-09-28 增补：随 ADR-018 撤回，第 1 项"计入应援值与榜单"与第 6 项"冲销应援值"不再适用，其余不变）
> 日期：2026-09-26
> 决策者：Cz（在 A 应援记录 / B 直播鸣谢 / C 站外播放特效 三选项中"只选择 A"）
> 关联：ADR-011（gift_kind 与库存策略分离）、ADR-018（榜单应援值）、`docs/plan/2026-09-26-slim-and-ux-appendix.md` 第 8 项、规范 §9.3/§12.2

## 背景

礼物四分类中 `gift_kind = VIRTUAL`（虚拟打赏）此前未定义"粉丝买到什么、何时算履约完成"。四个对标站的做法都不可取：guanlanvision 要粉丝付款后自己发邮件到个人邮箱等主播播特效；starvideoai/vividlivestar 未说明交付物；这类"站外播放特效"模式也是 PSP 严审的高风险类目。

## 决定

虚拟礼物的交付物是**数字应援凭证（应援记录）**：

1. **含义**：粉丝购买虚拟礼物 = 为艺人留下一条永久应援记录（订单快照 + 私密留言 + 可选署名），并按 ADR-018 计入该艺人当期应援值与榜单。不承诺直播鸣谢、不承诺播放特效、不产生余额。
2. **履约状态机**：支付聚合进入 PAID 后，系统自动将该订单中 VIRTUAL 行的履约推进至 DELIVERED（actor=system，写审计），无需运营动作。实现上为 VIRTUAL 行开放受控的 PENDING→DELIVERED 系统直达跳转（规范 §12.2 的兼容扩展，随榜单合同一并冻结）；混合订单中实物行仍走 PENDING→PREPARING→DELIVERED。
3. **粉丝可见文案**：查单页对 VIRTUAL 行显示"应援已送达艺人的应援记录"语义（七语言），不复用实物的"准备中/已送达"叙事；成功页与邮件同步调整。
4. **PSP 申报口径**：对外统一表述为"数字应援凭证 / 由平台履约的应援展示服务"，即时电子交付；严禁 donation / tipping / 打赏措辞（见 PSP 调研三家的类目结论）。
5. **管理中心**：VIRTUAL 礼物不出现"标记准备中/已送达"操作；其余（上架、价格、留言审核、退款）不变。
6. **退款**：沿用既有退款状态机；退款成功即按 ADR-018 冲销应援值。

**方案 B（承诺直播鸣谢）** 保留为未来可选升级档（需先定义鸣谢排期与凭证），本期不实现。
**方案 C（站外播放特效）** 明确不做：依赖站外平台配合、踩直播平台条款、PSP 类目风险最高。

## 后果

- 虚拟礼物成为零边际履约成本的商品线，运营负担集中在实物三类。
- 拒付抗辩依据 = 即时电子交付的应援记录 + 订单快照 + 查单访问日志；弱于实物物流凭证，因此商户申报以实物类目为主体、虚拟类目渐进开通（launch-plan §3.4）。
- 通知模板需新增 VIRTUAL 专用文案 key（七语言，en 源先行）。

## 验证

- 单元：VIRTUAL 行 PAID→DELIVERED 自动跳转、混合订单分行推进、退款冲销联动。
- 集成（真实 PG）：含 VIRTUAL+PHYSICAL 混合订单的支付入账后，履约行状态分别正确；重复入账事件不重复推进。
- 浏览器：查单页 VIRTUAL 行文案七语言正确，无"准备中"误导。

## 增补（2026-09-29）：可保存的应援凭证

用户在"查单页展示可保存凭证 / 暂时下架虚拟礼物 / 维持现状"三个选项中选择前者（方案 a）。F2 取消后，粉丝买虚拟礼物需要一个看得见、能保存的交付物，本增补就是 ADR-019 第 1 项"应援记录"的粉丝端出口。执行者 Claude（Windows 端），进度条目 L3-09。

- 位置：私密查单页和付款成功页；每个已送达（DELIVERED）的虚拟礼物行一张凭证卡片。
- 内容：艺人照片与名字、礼物名称与数量、送达日期、订单公开短号、粉丝可选署名。**不含**私密留言、金额和邮箱。措辞沿用第 4 项"数字应援凭证"，不出现 donation/tipping/打赏。
- 保存：粉丝点"保存图片"，由浏览器在本地生成 PNG，不上传、不留服务器副本。整行退款后显示为已撤回，不再提供保存。
- 视觉：沿用当前商城主题（默认黑金），七语言。
- 边界：只读取现有订单访问数据，不改变履约状态机、通知时机或 ON_HOLD 语义（这些属于 L3-08）。邮件里的凭证入口随 L3-08 的通知文案一起处理。

### 署名的取法（2026-09-29 用户决定）

规范 §11.1/§11.3 规定完整显示名只能经受保护入口“先审计再解密”读取，不得进入普通查单响应，所以凭证不自动带出下单时填的署名。用户在“保存时现填 / 不放署名 / 新增受保护读取入口自动带出”三项中选择前者，并补充“粉丝也可以选择不填或者匿名”：

- 保存凭证前，粉丝三选一：不显示署名（默认）、匿名粉丝、填写名字（1–40 个字符）；
- 填写的名字只在本机生成图片时使用，不上传、不保存，也不回写订单或 support intent；
- 凭证上来自服务器的部分（艺人、礼物、数量、送达日期、订单短号）仍只读取查单数据。

为此查单数据只读增加两项：虚拟礼物行的送达时间，以及该行是否已被成功退款全额覆盖（按 `refund_items` 与成功退款计算）。
