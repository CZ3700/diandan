## 关键决策及理由

- **拒付败诉按整单撤回**：`disputes` 按支付尝试挂在订单上，没有行级分配。订单的 `dispute_status` 只能按 NONE→OPEN→WON/LOST 单向变化，LOST 是终态（`database/migrations/0004` 的触发器、`packages/domain/src/dispute-state-machine.ts`）。直接用查单已经读到的订单行，不用新写 SQL。
- **撤回文案不区分原因**：原文写死了“全额退款后撤回”，拒付时不准确。七语统一改成“该礼物的款项已退回”，合同里的 `revoked:boolean` 也就不用改。
- **拒付路径没有端到端验收**：stg 的 TEST 支付模拟器（`apps/api/scripts/local-experience-services-psp.mjs`）只能模拟付款和退款，补拒付入口要改 TEST 工具链，不值得。拒付路径由投影单测覆盖，进度表里写明了这个缺口。
- **撤回卡片不用 opacity**：整张卡片半透明会连文字一起变淡，对比度不达标。上一轮只对可保存的卡片跑了 axe，所以当时没发现。以后所有“失效”状态都不要用 opacity 表达。
- **L2-15 手机焦点位用最左边完整卡片**（用户选定）：和现有的 `scroll-snap-align:start` 一致，不改布局。“完整”按 1px 容差判断，所以滑动中左边那张一被切掉，波峰就交给下一张，这正是“边滑边切换”。
- **L2-15 位移只在 STANDARD 动效下出现**：沿用礼物卡片的约定（`presentation.css`），SUBTLE 和 NONE 一律不做位移。玻璃是高亮状态，不算动画，所以各档动效下都显示。
- **轨道向页边距外延 12px**：手机的页边距是 16px，外延 12px 不会造成页面横向溢出；这样浮起的托框不会被滚动区裁掉，第一张也仍然和标题对齐（已验收）。
- **本机不用 `output/checks/f1-03/harness` 假 API 做前台验收**：它是早期写的，合同已经变过很多。本轮所有浏览器验收都在 stg 真实域名上做，改一次部署一次，一轮约 5 分钟。
- **L2-16 用户范围**：指商城配色（后台“店铺装修”里选），不是后台界面本身的外观；四款都要：樱花粉、晴空蓝、象牙金、珍珠灰。
- **stg 正式构建方案的六项决定**：见方案第 7 节。要点：
  - test 层只放开 `LOCAL_ACCOUNT`；
  - 部署时停机再构建；
  - 启动时核对构建戳记；
  - 加服务器结构化事件日志；
  - 这次只算“正式编译产物的浏览器验收”完成，正式配置路径留到正式 staging。

## 环境注意

- **测试超时**：`check:dev` 的测试阶段在负载下必定会撞上几条 5 秒冷启动超时，turbo 在第一个失败处就停，后面的包不再跑。固定做法：
  1. 先跑 `pnpm exec turbo run test --output-logs=errors-only --continue --concurrency=1`；
  2. 失败的包用 `pnpm exec vitest run --config ../../vitest.config.ts --root . --maxWorkers=4` 逐包复跑（persistence 用 6）；
  3. 最后单独跑 `turbo run build`。

  本轮出现过超时的有：application 的 storefront-commerce；api 的 storefront-commerce-route；admin 的 instrumentation、management center、admin-access-bff；storefront 的 specimen 三条和 rum 两条；persistence 的三条。全部与改动无关，复跑都通过。
- **stg 部署**（每次都这样做）：
  1. `git push staging v2/r1-production`；
  2. 用 `ssh xiadan-app 'bash -s'` 执行带 `set -o pipefail` 的构建脚本，日志回传到 `output/checks/<条目>/`，确认有 `build exit 0`；
  3. 读开发日志的报错数留证：`grep -c '"level":"ERROR"' ~/app/apps/*/.next/dev/logs/next-development.log`；
  4. `ssh xiadan 'systemctl restart fan-support-remote-test@stg'`；
  5. 用 curl 抽查动态路由。

  本轮 4 次重启都是一次就绪，没有再出现“全部 404”。
- **后台验收账号**：`qa.check` 由脚本随机生成密码，经 SSH 标准输入交给服务器命令，用完暂停，参考 `output/checks/l3-09a/stg-certificate.mjs`。不读任何凭据文件。
