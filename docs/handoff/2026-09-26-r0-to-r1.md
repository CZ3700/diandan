## 关键决策及理由

1. **V2 方案取代原 Phase/Task/Lane 流程作为新工作的推进方式。** 原流程把大量精力耗在"证据生产"上：完整门禁从 3 分钟涨到 36 分钟；验收截图/日志入库导致 git 膨胀；MASTER.md 单行 2,060 字，人已读不动；10 个 IN_PROGRESS 实际无人执行。代码只占 36.5%，验证脚本和测试各占约 30%。保留有价值的部分：S.U.P.E.R 架构原则、编码标准、测试先行、真实集成测试。原 phase 文件留作历史验收参考。

2. **支付"热更新" = 静态预置适配器 + 配置激活，而不是运行时插件。** 规范 §13.3 与安全基线都禁止运行时加载支付代码。三家 PSP 沙盒都免费、即时、无需审批，所以适配器可以现在开发，不等商户号。商户号到位后，只需在 P5-05 配置后台录凭据 → 绑 webhook → 发布灰度（≤1 天），再加一笔小额真实交易验证。接线点是 `apps/api/src/payment-runtime-composition.ts:285` 的 `deployedProviders`，生产入口目前传空，所以支付在生产中被静默禁用。顺序 **Stripe → Airwallex → PayPal** 的理由：Stripe 沙盒工具链最顺（CLI 转发 webhook），先立适配器范式；Airwallex 是主候选商户（对标站两家实证）；PayPal 形态差异最大（组件 + capture 回调 + RSA 证书验签），放最后。

3. **虚拟礼物 = 数字应援凭证（ADR-019，用户"只选 A"）。** 付款后系统自动完成履约并计入应援值，不承诺直播鸣谢或站外特效。理由：零履约成本；站外播放特效依赖外部平台配合，且 PSP 类目风险最高。PSP 申报严禁 donation/tipping/打赏措辞，以"实物礼品零售 + 代购履约"为主体类目（用户已开始申请商户）。

4. **榜单是订单事件的可重建投影（ADR-018）。** 投影不能成为第二真相源；退款和拒付按事件自动冲销；粉丝榜默认匿名，显示应援值积分而非金额，取整到 10 分。隐私红线：永不返回邮箱、真名、单笔明细（对标 starvideoai 公开粉丝邮箱是反面教材）。首发做月榜 + 赛季榜。

5. **验收证据出库，本地门禁不再依赖入库证据。** 实测入库证据早已过期：Next 升级到 16.3.6 后没重新生成，当前 HEAD 在任何机器上跑完整 `pnpm check` 都会失败。CI 的 quality 套件会先跑 `verify:ui-*:browser` 重新生成证据再 `check`，所以 CI 中（`CI=1`）仍然强制校验；本地用 `--require-browser-evidence` 可选开启。策略集中在 `scripts/browser-evidence-policy.mjs`。464 份 md 验收摘要保留跟踪，因为进度文档引用了它们。

6. **门禁修复坚持"修真缺陷、不掩盖"。**
   - 保留 `shell: false` 安全属性：Windows 上用 `node.exe + corepack.js` 启动，不改用 shell。
   - 设计基础门禁的路径比较是真缺陷：在 Windows 上既误报又漏检（假绿），已修复。
   - Windows 跳过的测试只限确实的平台限制，并写明原因：无权限创建文件符号链接；原生 PG 测试集群依赖 POSIX 权限位和 Unix socket。能保留的覆盖都保留了，例如回归快照测试的穿越和绝对路径两个用例照常执行。Linux CI 和 Mac 仍然全量执行。

7. **`.gitattributes` 强制 LF。** 本机 `core.autocrlf=true`（系统级 gitconfig），而 prettier 默认要求 LF，不加约束的话新 checkout 会大面积格式失败。`research/root-evidence/**` 是原始 HTTP 抓包，用 `-text` 保留 CRLF 字节。

8. **不做 `git filter-repo` 历史重写（瘦身 ③2）。** 它能把 .git 从 533M 降到约 55M，但会重写所有提交哈希、需要 force push、所有现有 clone 作废。当前收益不值得，留待主干稳定后再议，或者永远不做。

9. **清除 Mac 带来的 node_modules 并重装。** pnpm 的符号链接解压后变成了 0 字节空文件，原生包全是 darwin-arm64，在 Windows 上完全不可用。

## 环境注意

- **每个 Bash 调用先执行 `source /c/Users/admin/.tools/xiadan-env.sh`。** 它把便携 Node 24.20.0 和 corepack 生成的 pnpm shim 放到 PATH 最前，并关闭 corepack 下载提示与 turbo 遥测。系统 Node 是 24.13.1，项目的 `engineStrict` 会拒绝它。turbo 需要 PATH 上有 `pnpm`，已通过 `corepack enable` 在便携 Node 目录生成 shim。
- **Bash 工具每次命令结束后 cwd 会重置**，一律用绝对路径：`/c/Users/admin/Desktop/下单/下单`。
- **Windows 无法创建文件符号链接**（未开开发者模式，EPERM）。测试夹具要链接目录时用 `symlink(..., "junction")`；必须测文件符号链接的安全测试按 win32+EPERM 跳过，并写明原因。
- **`core.autocrlf=true`**：`.gitattributes` 已强制 LF。用 Write/Edit 新建的文件默认就是 LF，没有问题。
- **门禁耗时**：`check:dev` 冷启动约 4 分钟，有缓存约 30 秒。完整 `pnpm check` 本机只能跑 22/24 段。做法是把 package.json 的 `check` 脚本按 ` && ` 拆开逐段执行，跳过含 `test:postgres`/`test:s3` 的段；逐段执行前要把 `node_modules/.bin` 加进 PATH。
- 长命令一律放后台运行，等完成通知；不要用 `sleep` 轮询（会被拦截）。
- `du`/`find` 扫全目录会超时（node_modules 和 output 很大），要限定范围并加 `timeout`。
- 本地体验脚本（`local:start` 等）里硬编码了 macOS 路径（`scripts/local-experience-browser-launcher.mjs:24-27`、`apps/api/scripts/local-experience-postgres.mjs:14`），**在 Windows 上未验证**，还需要 Docker 和 PostgreSQL 18。
- prettier 的 `format:check` 只覆盖指定目录（README.md、apps、packages、scripts 等），`docs/`、`AGENTS.md`、`CLAUDE.md`、`.agents/` 不在范围内。
