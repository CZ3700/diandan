各项要点：

- **F1-1 虚拟礼物自动履约**
  - VIRTUAL 行在支付进入 PAID 后由系统推进到 DELIVERED（actor=system，写审计）；混合订单里的实物行照常走流程。
  - 查单页、成功页和邮件使用 VIRTUAL 专用文案（七语言，en 源先行）。
  - 后台不为 VIRTUAL 行显示"准备中/已送达"操作。
  - 这是 F2 应援值入账的前置。
- **F1-2 订单公开短号**
  - 新增 `public_order_no` 列并加唯一约束，格式为"FS- + 6 位 Crockford base32 随机码"，冲突时重试（规范 §5.8 禁止连续号）。
  - 查单页、成功页、邮件、后台和客服都显示短号，UUID 只在内部使用。
  - 只凭短号不能读取订单，仍需访问会话。
- **F1-3 首页改版、四分类、价格直显第二阶段**
  - 满屏偶像海报首屏。
  - 四分类磁贴链接到 `gifts?kind=`，目录 API 增加 kind 参数。
  - `/gifts` 与首页的目录显示价格、规范 URL 去掉隐含作用域、页眉/页脚隐藏"选择地区"。
  - 必须保持"页壳与内容先于商业上下文流式输出"，见 ADR-017 增补。
- **F1-4 送达证明照片**
  - 运营标记送达时上传 1–3 张照片，复用媒体管线（EXIF 剥离、重编码、内容寻址）。
  - 新增 `fulfillment_proof` 关联表。
  - 照片只在查单会话内展示，不进任何公开页面；后台提示运营裁掉第三方人脸与地址信息。
- **F2 榜单与公会赛**
  - 投影可以从订单/支付事件重建，退款和拒付自动冲销。
  - 隐私红线：永远不返回邮箱、真名或单笔明细。
  - 公会赛走既有内容发布体系。
  - 建议拆成子里程碑：合同与迁移 → 投影与冲销 → API → 前台页面 → 后台公会赛录入。
- **F3-1 客服入口与站点信息页**
  - 可配置的联系方式：邮箱，以及 WhatsApp/LINE/Telegram 任选。
  - FAQ、关于我们、交付说明三个页面。
  - 本次只做页面框架与内容模型；正式文案属于业务侧工作。

仍未决定、不在本次范围内：上线缺口 B5（选填粉丝的直播平台账号，方便致谢）。它与 ADR-019"不承诺直播鸣谢"的方向可能冲突，要做必须先由用户决定。
