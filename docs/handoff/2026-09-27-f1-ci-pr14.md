## 关键决策及理由

1. **用户决定：关闭 PR #14，R0 既有失败转入"CI 四组回归失败修复"**。原因：F1 相关问题都已修复并在 CI 上确认；剩下两个阻塞都是 R0 就有的问题，每轮 CI 要约 85 个 job-分钟，5 轮已用掉约 400 分钟。**以后为 CI 再开 PR，仍须先问用户。**
2. **用户决定：Hero 压力格只查无溢出和无截断**（没选"加大 Hero 最小高度"或"自托管字体"）。实现上仍要求确实发生加载→就绪切换，左边界、顶部和宽度 1px 内不变，只允许高度、锚点和文档高度向下增长。失败态检查和常规视口不变。
3. **0038/0039 直接修改而不是新增迁移**：这两个迁移只存在于本分支，从未部署过。修改后重新生成了 `manifest.json`，目录快照不变。修法照搬 0039 回填 `orders` 时已经在用的 `DISABLE TRIGGER USER`。回填期间不跑延迟校验器；回填内容由快照函数生成，本身就是一致的。
4. **每轮只加诊断、不做猜测性修复**：好让每轮的结论可归因。例外是 `45d8388`（扩容），事后证明无效，已如实记录。
5. **`local-experience-browser.mjs` 和 `accessibility-flows.mjs` 不在 CI 回归计划里**（`scripts/regression-plan.mjs` 没有它们），F1-3/F1-4 交接误记为有 CI 覆盖。前者用的是显式市场参数，不受唯一市场影响；后者已适配。
6. **journey 第 2 轮的 `PUBLICATION_FAILED` 没有复现**。第 3–5 轮 `local:stop` 都没输出 PG 失败行，记为偶发。

## 环境注意

- **PR 开着时，往分支推送会重跑整套 CI**；`ci.yml` 的 concurrency 会取消进行中的运行。PR 关闭后推送不触发 CI（本会话已验证）。
- **CI 诊断方法**：
  - 运行中的 job 日志：`gh api repos/CZ3700/diandan/actions/jobs/<id>/logs`（`gh run view --log-failed` 要等整个 run 结束）；
  - 产物：`gh run download <run> -n regression-<suite> -D output/checks/...`。catalog 产物约 137MB，要放后台下载；
  - 回归 runner 在套件内**遇到第一个失败就停**；产物收集器只收 `.json/.png/.md/.txt`，新增诊断输出要用这几种扩展名，并且先脱敏；
  - `check:ui-composites` 在 CI 上要求浏览器证据，所以 quality 里的 `pnpm check` 只能排在 UI 浏览器验证之后。
- **本机能跑的 CI 片段**：
  - `verify:ui-composites:browser`：只有最后的原生 Chrome 缩放那步跑不了（Windows 版 `chrome --version` 不往 stdout 输出版本号）；
  - `verify:ui-motion:browser` 跑不了（证据锁用了 POSIX 的 `ps -o`）；
  - storefront 的 preview 生产构建可以复现，环境变量见 `apps/api/scripts/gift-storefront-next.mjs`，媒体源要用 `https://media.example.invalid:<端口>`。
- **PG 探针**：临时脚本放在 `packages/persistence-postgres/scripts/` 下，从 `../dist/index.js` 导入 `runMigrations` 和 `withEphemeralPostgres`，跑完即删。
  - `MigrationExecutionError` 不带 cause，要拿 SQLSTATE 就挂 `Client.prototype.query` 钩子；
  - `withEphemeralPostgres` 会改写回调里抛出的错误，要在回调内先打印安全信息；
  - 用 `session_replication_role = replica` 插入历史行，可以绕过触发器和外键，但 CHECK 约束照样生效。
- **改了迁移 SQL 后**要执行 `corepack pnpm --filter @fan-support/persistence-postgres migrations:manifest` 重新生成校验和；`postgres-integration.mjs` 会比对目录快照。
- Git Bash 的 `/tmp` 不是 scratchpad：备份要写到 scratchpad 的绝对路径，还原后要核对内容（本会话 0039 差点被还原成未修复版本）。
- `check:dev` 的 test 段：persistence-postgres 有 2–3 个冷启动 5 秒超时，串行时也会出现，用 `npx vitest run --maxWorkers=12` 单跑这个包确认；其余包用 `turbo run test --concurrency=1 --filter='!@fan-support/persistence-postgres'`。
- 以往交接里的环境注意（便携 Node 与 PG、Python 写 LF、PL/pgSQL 的 CASE 陷阱、查单页本机验收要用生产构建和 TLS 边缘）仍然有效。
