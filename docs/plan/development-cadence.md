# 开发与验证节奏

> 2026-09-08；用于缩短开发反馈，不改变业务约束、任务完成标准或阶段门。

## 已生效：按改动验证，在集成检查点集中验收

1. **复用未变化的基线。** 记录提交、输入指纹、命令与结果；仅在相关源码、依赖、配置和验证工具未变化时继承对应证据。缓存命中如实记录，旧结果不能冒充本次执行。
2. **采用快速定向循环。** 先有效 RED，再最小实现与受影响测试；日常检查包含格式、lint、架构边界和必要类型/构建。快速检查不代表真实 PostgreSQL、S3、浏览器或正式验收通过。
3. **一个集成候选统一完整检查。** 各独占模块先交付定向结果，由协调者冻结候选后统一执行完整 `pnpm check`；不让多个代理重复跑同一套约 20 分钟检查。支付、权限、迁移及库存变动仍须实际对应集成测试和非作者复审。
4. **只复验受影响 UI。** 页面或共享组件改变时运行其真实浏览器、键盘、错误态和 reduced-motion 回归；后端独立变化不自动触发所有 P2 浏览器。共享组件、字体、构建输入变化必须刷新受影响证据，不能绕过已有指纹门。
5. **代表样本定位，完整矩阵验收。** 性能调试先用明确指定的瓶颈页面及语言、每组多次同条件采样；优化收敛后再执行七语言完整 21 组 × 3 次矩阵。诊断样本不能替代 Phase 3 的原性能预算或完整验收。
6. **证据保持短入口。** 每个候选保留一份结果摘要、源码清单和原始运行索引；写明命令、退出码、测试范围、缓存、失败和剩余门。复审引用原证据，不复制同样的大包，不覆盖失败历史。

快速检查入口为 `scripts/check-development.mjs`，实际命令如下：

- `pnpm check:dev`：默认所有 workspace，包含消费者；依次执行 workspace/domain 边界、既有格式/lint 检查，再串行执行 Turbo typecheck、test、build，保留缓存，任务并发上限为 2。
- `pnpm check:dev --plan`：仅输出 JSON 执行计划，不启动检查；可与下面的包筛选组合。
- `pnpm check:dev --filter @fan-support/cart`：选择精确包；改为 `@fan-support/cart...` 则包含其传递依赖。两种筛选均不主动选择消费者，Turbo 既有任务依赖仍生效；需要消费者保障时使用默认无筛选命令。

包筛选不缩小既有格式/lint 和 workspace/domain 检查范围。不接受未知包、glob 或 Git 筛选；首项失败即停止并保留非零退出码。所有模式都不替代真实 PG/S3、浏览器或正式验收，旧 `pnpm check` 和 CI 入口保持不变。

## 采样有效性

- 固定被测构建和 fixture，记录 URL、locale、market/currency、视口、采样工具及版本；性能采样时不并行构建或其他浏览器压力任务。
- 先验证目标实体与实际内容成功，再解释性能结果。HTTP 200 的临时不可用页不能算作成功内容样本。
- 导航、内容或采集失败须保留原始结果并使该轮无法验收；不得删掉失败再补一份好结果凑足三次，或挑选最佳一次。
- 中位数只总结其明确样本集合；代表组结果须标为诊断。实验室指标不能替代真实 RUM、真机或真人读屏。

## 始终保留的交易与发布边界

- PostgreSQL 仍是唯一业务真相源；加购服务端重验艺人、礼物/规格、当前收礼资格、市场/币种、价格和库存，不能信任浏览器金额或公开报价 DTO 作为授权。
- cart item 与加密 support intent 同事务，幂等重试不重复创建；同键异请求冲突。库存策略与礼物类型独立，不造无限现货，库存预占按 P4-03 范围实施。
- 私密留言、完整显示名、访问 token 不进入公开 DTO、日志、分析或 URL；支付最终状态只接受可信 webhook 或受权审计的 reconcile。
- 快速检查、内部 TEST 素材和本地成功不替代关键译文批准、真人运营/读屏、production-like staging、真实支付退款或正式发布门。现有失败和未完成状态必须继续可见。
