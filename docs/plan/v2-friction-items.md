# V2 粉丝体验减摩擦（方案 §4 第 1/2/4/5 项）：实现记录

> 依据：V2 方案 §4、`2026-09-26-slim-and-ux-appendix.md`（粉丝体验变更清单）、规范 4.0.0 §0.2 与 §12.2

## 第 1 项：同意框合一（完成）

- 结账表单只有一个勾选框，旁边是一句话："我已阅读并同意《A》、《B》、《C》和《D》。"每个政策标题都是链接，点开后展开结账概要里对应政策的全文并滚动过去；点链接不会勾选。
- 法律留痕不变：创建结账会话时，仍为每个政策分别提交 policyKey、版本和翻译版本。合同、服务端校验与同意哈希都没有改动。
- 文案：
  - 新增 `checkoutConsentAll`（含 `{policies}`）与 `checkoutConsentTitle`（标题包装，中文《》，日文「」），替换原来的逐项 `checkoutConsent`。
  - 列表连接符由 `Intl.ListFormat` 按语言生成。
  - 七种语言仍为 DRAFT，等 R1-2 审校流程确认。
- 兼容：唯一的勾选框保留 `data-checkout-policy` 属性（值为 `all`），现有 5 个浏览器回归脚本不用改。
- 延后到对应市场上线时再做：
  - 欧盟"立即履约放弃撤回权"需要单独勾选，计划做成按市场配置的 extraConsents；
  - 德国的付款按钮需明示付款义务（Button-Lösung）。

## 第 5 项：状态四态化（完成）

- 映射函数放在共享包 `@fan-support/orders`（`fanOrderProgress`、`fanItemStage`），单测穷举全部 500 种状态组合。规范 §12.2 要求这类映射必须有单元测试。
- 粉丝只看到一条时间线：已付款 → 准备中 → 已送达，当前步骤带 `aria-current="step"`，不显示任何步骤的发生时间。时间线之外的结局直接替换时间线：
  - 付款确认中；
  - 已退款（全额退款优先于其他状态）；
  - 已取消。
- 部分退款时时间线照常显示，另加一行说明。
- 运营核查暂停（ON_HOLD，对应 PAID_REVIEW）对粉丝显示为"准备中"，礼物行同样如此。
- 付款争议不出现在粉丝文字中；争议进行中或已判负时，也不给出"正在准备"之类的进度承诺。
- 四个规范状态轴仍以 `data-order-*-status` 属性保留在时间线元素上，供回归脚本和客服工具读取，现有脚本不用改。
- 已知缺口："退款中"需要查单读模型提供进行中退款的标记（合同 + PostgreSQL 查询扩展，本机无法验证），留作后续；目前只能显示已完成的全额或部分退款。
- 旧的"付款争议""订单"等标签文案暂时保留，等 R1-2 审校时统一清理，避免现在反复改动审校哈希。
