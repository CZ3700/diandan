## 1. 结论一句话

榜单是订单与支付真相的**可重建投影**：每当一张订单的付款、退款、争议或复核状态变化，worker 按该订单的当前真相重算它对各周期的"贡献"，再由贡献汇总出艺人榜与粉丝榜。公开接口只返回取整后的应援值、名次和"匿名粉丝/审核通过的昵称"。公会赛成绩作为新的日常内容类型，走既有的发布体系。

## 2. 摸底事实（决定了设计，均已在代码里核实）

1. **没有可用的有序重放游标**。`outbox_events.id` 是随机 UUID，没有序列、水位或提交顺序字段；按 `created_at` 取会漏掉晚提交的事件。ADR-018 草图里的 `last_event_id` 条件增减分做不到。
2. **只有"已付款"有订单级 outbox 事件**（`ORDER_PAYMENT_CONFIRMED`）。退款、争议发的是退款/争议聚合自己的事件，只带 ID 与状态；订单转为部分退款、全额退款、争议中，都只写 `order_events`。所有事件 payload 只有 ID 和状态，金额、行、币种都要回源表读。
3. **通用 outbox 分发器不适合做投影**：每个消费者都会收到全部事件类型（无类型过滤）、按"已处理集合"做全表 `NOT EXISTS` 扫描（架构审查 C5）、处理记录只追加不可重置、死信恢复写死只认通知消费者。
4. **钱在哪**：已付 = 当前付款尝试（SUCCEEDED）金额；退款按行分配在 `refund_items`（只计 SUCCEEDED 的退款）；争议是订单级金额、无行分配；行的艺人在 `order_items.idol_id`，行金额 `line_total_minor`，币种每单一种。`order_items.gift_kind` 已是购买时快照（F1-1）。
5. **粉丝身份**：`customer_contacts.email_lookup_hmac`（KMS HMAC，带 `lookup_key_version`）已经是"邮箱的 keyed HMAC 摘要"。每次结账新建一行联系人，所以这是唯一能把同一粉丝的订单串起来的标识。数据清除（PURGED）时它会被置空。
6. **昵称**：加密在 `support_intents.display_name_ciphertext`，没有任何 worker 路径解密它。人工审核读取时昵称与留言一起显示；但**只有昵称、没有留言的行可能一直处于 PENDING**，自动审核的证据也只覆盖留言。
7. **公开读接口**现在一律零 TTL（`public, max-age=0, s-maxage=0` + ETag），且有测试与基础设施断言钉住；ADR-018 要的 30–60 秒 TTL 需要新的响应头辅助函数与相应测试。
8. **没有埋点管线**：§16.3 事件只存在于文档，F3-2 才补。F2 只预留事件名，不实现上报。
9. **加一种日常内容类型（公会赛）要改很多处**：`content_publications` 的类型 CHECK 与外键列、发布头表、0006/0022 里逐类型列举的校验函数、清除路径、合同联合类型、渲染与持久化映射。

## 3. 关键设计决定

### 3.1 按订单重算贡献，不做事件增减分

- **贡献表**：`leaderboard_contributions(order_id, period_id, idol_id, fan_key, points, paid_at, …)`。每行是一张订单对一个周期、一位艺人的贡献。
- **分数表**：`idol_support_scores`、`fan_support_scores`。每次重算后，只对受影响的（周期, 艺人）与（周期, 粉丝）键，按贡献表重新汇总，不做增量加减，所以不会漂移。
- **计算**：纯函数放在 `packages/domain`（单测覆盖计分、冲销、取整、周期边界）。仓储层读取订单的真相快照，写入贡献并重汇总，全在一个短事务里完成，按订单加咨询锁以串行化。
- **性质**：
  - 幂等：重复触发的结果不变；
  - 与顺序无关：乱序到达，最终仍以真相为准；
  - 重建即清表后对所有已付款订单重算，天然满足 ADR-018 的"全量重放 = 按订单直接重算，逐行一致"。

### 3.2 变化来源：待重算订单队列（数据库触发器登记）

- 新表 `leaderboard_dirty_orders(order_id PK, generation, marked_at, lease…)`。以下变化由 AFTER 触发器登记该订单：
  - `orders` 的付款状态、争议状态变化；
  - `refunds` 的状态变化；
  - `fulfillments` 进入或离开 ON_HOLD；
  - `support_intents` 的审核或隐私状态变化；
  - `customer_contacts` 的清除或 HMAC 变化。
- 触发器只做"登记"，不改业务状态。选它而不用 outbox 消费者，原因见 §2 第 1–3 条；它也覆盖了没有 outbox 事件的变化（审核、清除）。这是本仓库第一处"写入型"触发器，需要在代码评审中确认。
- worker 用既有的轮询运行时（与管理中心、发布清除同一模式）按租约认领，重算后按 generation 条件删除。
- **ADR-018 的 `leaderboard_projection_state` 改为记录重建运行**（开始、完成、处理订单数），不再作为事件游标。

### 3.3 计分规则

- **计入条件**（全部满足）：
  - 付款状态为 PAID 或 PARTIALLY_REFUNDED（REFUNDED 计为 0）；
  - 争议状态为 NONE 或 WON（OPEN 暂停计分，LOST 移除）；
  - 没有 ON_HOLD 的履约行。这就是"异常订单人工复核不计分"：迟到付款复核与运营手动挂起都覆盖。
- **金额**：行净额 = 行金额 − 该行 SUCCEEDED 退款分配；按艺人汇总；每单一种币种。
- **折算**：规则修订里按币种各有一条折算率（点数/最小单位额），`points = floor(净额 × 点数 ÷ 每单位额)`。
  - 没有折算率的币种不计分，后台提示。
  - 规范禁止浮点汇率换算，所以不做 USD 汇率。
- **显示**：分数按 10 分粒度向下取整后显示并排名。同分并列名次，先达到该分的排在前面。
- **周期归属**：按付款成功时间（`payment_attempts.succeeded_at`）落入所有包含它的周期（同时计入月榜与赛季榜）。
  - 退款或拒付发生在周期结束后，照样冲销原周期；已结束的榜单也会随之变化。规则页公开说明这一点。
- **粉丝键**：直接用 `customer_contacts.email_lookup_hmac`（+ 版本）。另立 KMS 用途要在结账时计算、无法覆盖历史订单；而贡献表本身按订单寻址，另立用途也换不来额外的隔离。
  - 代价一：密钥轮换会把同一粉丝拆成两个身份，轮换宜放在月初。
  - 代价二：联系人清除后，该粉丝从粉丝榜消失，但艺人榜不受影响。

### 3.4 粉丝榜显示

- 默认显示"匿名粉丝"。
- 显示昵称需同时满足：
  - 该粉丝在本周期**最近一笔**计入订单的**每一行**都选了昵称；
  - 该行的审核状态为 APPROVED 且 `moderation_decision_kind = 'HUMAN'`（自动审核证据不覆盖昵称，见 §2-6）；
  - 隐私状态为 ACTIVE。
- 昵称明文存在单独的 `leaderboard_nicknames(support_intent_id PK, display_name, audit_log_id)`：
  - worker 在审核通过后做一次带审计的解密（模式同通知的联系人读取：审计 + 回执 + 数据库授权触发器）；
  - `support_intents` 离开 APPROVED/ACTIVE 时由触发器删除该行；读取时再联表确认当前状态。
- API 永不返回邮箱、HMAC、订单号、金额、币种或单笔明细（ADR-018 隐私红线），合同测试扫描这些字段。

### 3.5 周期

- **月榜**：按 UTC 自然月（北京时间每月 1 日 08:00 切换），由 worker 提前建好当月与下月，规则取当月开始时生效的修订。
- **赛季**：运营在后台创建（名称按原文直发 + 起止时间）。
  - 创建时对窗口内已付款订单登记重算；
  - 赛季不重叠。
- 周期状态按时间推导：未开始、进行中、已结束。只有"撤下"需要写库（误建的赛季）。

### 3.6 公会赛成绩

- 新的日常内容类型 `GUILD_MATCH`：
  - 结构化字段：赛事名、赛事时间、名次列表（名次 + 艺人外键）、来源说明、原文语言；
  - 海报一张，复用 PORTRAIT 角色（4:5），不新增媒体角色。
- 发布走 `DIRECT_OPERATOR_V1`，名次列表放在受修订守卫保护的子表里，所以 `?idolId=` 查询与外键完整性都能成立。
- 这是 F2 里改动面最大的部分（§2-9），单独成为 F2e。

## 4. 数据模型（迁移 0043 起，按子里程碑分批）

| 表 | 要点 |
|:--|:--|
| `leaderboard_rule_revisions` / `leaderboard_rule_rates` | 只追加；修订号、生效时间、显示粒度（10）；每币种一条折算率（点数、每单位额，均为正整数） |
| `leaderboard_periods` | MONTH/SEASON、[starts_at, ends_at)、规则修订、赛季名称原文与语言、撤下标记；月榜 (kind, starts_at) 唯一；赛季不重叠（排斥约束） |
| `leaderboard_contributions` | (order_id, period_id, idol_id) 唯一；points ≥ 0；fan_key 可空（联系人已清除）；display 候选行 |
| `idol_support_scores` / `fan_support_scores` | (period, idol)、(period, fan_key) 主键；points、计入订单数、首次达到时间 |
| `leaderboard_dirty_orders` | 待重算队列，generation 与租约 |
| `leaderboard_nicknames` | 审核通过的昵称明文，随审核或隐私状态撤销而删除 |
| `leaderboard_rebuild_runs` | 重建运行记录 |

- 投影表可清空、可删除，不影响订单与支付。
- down 迁移：规则与周期有数据时拒绝回滚（属于运营配置），投影表直接删除。
- 每个迁移都带"已有数据的升级"测试（参照 `postgres-backfill-upgrade.mjs`）。

## 5. 接口（Zod 合同先行，只读公开）

| 路径 | 说明 |
|:--|:--|
| `GET /api/v1/leaderboards/periods?kind=` | 周期列表与存档（不含撤下的） |
| `GET /api/v1/leaderboards/idols?periodId=&limit=` | Top50 上限；名次、艺人（已发布才显示）、取整分 |
| `GET /api/v1/leaderboards/fans?periodId=&limit=` | Top50；名次、昵称或匿名、取整分 |
| `GET /api/v1/leaderboards/rules` | 当前规则：粒度、各币种折算、周期边界说明 |
| `GET /api/v1/guild-matches?idolId=&page=` | 已发布公会赛成绩 |

- 缓存：API 进程内 30 秒 TTL + `Cache-Control: public, max-age=30, s-maxage=60`。这需要新的响应头辅助函数，并改动钉住零 TTL 的测试与 OpenAPI 说明。CDN 侧放到 R1-6 缓存条目统一处理。
- 功能开关：环境变量 `FAN_SUPPORT_LEADERBOARDS_MODE=enabled|disabled`（缺省 disabled）。关闭时路由返回 404，前台隐藏入口。

- 前台：
  - `/:locale/leaderboards`：艺人/粉丝两个标签页、周期切换、赛季存档；
  - `/:locale/leaderboards/rules`；
  - 首页模块：Top3 + 最新公会赛；

  - 七语言，文案 DRAFT，更新审校哈希；每条路由 7 个页面文件；

  - 规则修订（新增折算率）、赛季管理、公会赛录入（一张图 + 短表单）；

## 7. 子里程碑与提交拆分

| 子项 | 内容 | 主要验证 |
|:--|:--|:--|
| F2a | 合同；迁移（规则、周期、贡献、分数、队列、重建记录）；领域计分纯函数；触发器登记 | 领域单测（计分、冲销、取整、边界、并列）；真实 PG：触发器登记、约束、带数据升级、down 拒绝 |
| F2b | worker 重算循环、月周期维护、重建与校验命令（`leaderboards:rebuild`、`leaderboards:verify`） | 真实 PG：付款→退款→争议→复核全路径，"增量结果 = 全量重建"逐行一致，重复与乱序不重复计分 |
| F2b2 | 昵称：带审计解密、昵称表、撤销触发器 | 真实 PG：未审核、自动审核、撤回、清除都不显示昵称 |
| F2c | 公开 API、缓存与响应头、功能开关、OpenAPI | 路由单测、隐私扫描合同测试 |
| F2d | 前台页面与首页、艺人页模块，七语言 | 本机假 API 夹具 + Chrome/WebKit，390×844/1440×900，键盘、减少动态效果 |

## 8. 不做与延后

- 周榜（ADR-018 首发只做月榜 + 赛季榜）。
- 实时推送、埋点上报（F3-2）、CDN 缓存（R1-6）。
- 按艺人分组的粉丝榜。
- 粉丝自助修改昵称或退出榜单：默认匿名，只有明示选择昵称才显示。

## 9. 需要用户确认的默认值

1. **折算率**：美元 1 元 = 10 应援值，显示按 10 分取整，相当于约 1 美元的粒度。其他币种在后台自行配置，没配置的币种不计分。
2. **月榜边界**：UTC 每月 1 日 0 点（北京时间 8 点）。
3. **已结束的榜单**：退款或拒付仍会冲销原周期，存档名次可能变化，规则页写明。
4. **计分暂停**：争议处理中和订单挂起期间暂停计分，结案后恢复或移除。
5. **昵称显示**：只显示人工审核通过的昵称；没有留言、只有昵称的订单也要人工审核后才会显示。
