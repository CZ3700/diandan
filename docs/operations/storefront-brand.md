# 站点 Logo 管理

入口：管理后台 → 店铺装修 → 品牌标识。此功能需要本项前后台、API 与数据库迁移一同部署。

## 日常操作

1. 为“浅色主题 Logo”上传深色文字或图形版本；为“深色主题 Logo”上传浅色版本。建议使用透明 PNG 或 WebP，横向组合标识更适合页头。
2. 检查两个底色上的完整图形，再查看商城手机、电脑预览。上传完成并不等于发布。
3. 保存草稿，确认预览后发布。发布后商城共用页头和页脚读取新的标识。
4. 如需更换，直接替换对应图片；如需显示文字站点名，移除该主题的图片，再保存并发布。
5. 历史版本可以恢复；恢复会产生一条新发布记录。品牌历史与配色、导航、海报分别管理。

上传失败可以重试，或取消本次文件选择并保留原 Logo。编辑和发布沿用现有内容权限；上传还需要媒体上传与版权确认权限。

没有对应主题图片、图片读取失败时，商城显示配置的站点名称；不会把另一份可能看不清的图片强行放上去，也不会自动反色。两张 Logo 可分别维护，切换主题时会选择对应的一张。

## 图片要求与范围

- 支持静态 PNG、WebP、JPEG、AVIF，最大 25 MiB。透明 PNG/WebP 通常最合适；不支持 SVG、动画或任意外部图片地址。
- 保留原比例与透明度，最长边缩至最多 1024 像素，较小图片不放大。不会自动裁切透明留白，原文件中不必要的大留白应在上传前处理。
- 原图留在私有对象存储；公开图经过完整解码、方向校正和元数据清理，以 WebP 保存。
- 本设置控制商城页头与页脚，不改变站点名称、浏览器图标、SEO、支付渠道、邮件或应援凭证。

## 部署与验收

- 应用数据库迁移 0064，并同步 API、管理后台和商城构建；旧环境在没有品牌发布记录时仍显示文字标识。
- 部署后用正常后台身份验证：上传浅/深两份图片 → 预览 → 保存草稿 → 确认公开页未变化 → 发布 → 刷新商城 → 更换并恢复历史。
- 复查 390×844、1440×900 与所有配色，确认标识完整、菜单和购物袋可操作；失败上传应保留当前图片，过期版本应提示重新读取。
- 数据库降级不能丢弃已有品牌记录；升级前沿环境现有备份流程保留数据库与媒体。实际迁移回退约束以 0064 脚本为准。
- 专项回归入口：`pnpm --filter @fan-support/api test:postgres:storefront-brand`。脚本使用临时 PostgreSQL 与受控 S3 环境验证签名上传、透明处理、草稿隔离、并发版本校验、发布、移除、历史恢复和降级保护；不连接公开 TEST 业务数据。
