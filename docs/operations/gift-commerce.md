# 礼物、价格与库存运营

关联：[内容发布流程](./content-publication.md)、[ADR-011](../decisions/011-gift-kind-inventory-policy.md)、P3-03。

## 新建与上架

1. 从后台礼物目录新建唯一 handle。选择礼物类型：虚拟、实体、心愿、周边或其他；类型只用于分类，不自动选择库存策略。
2. 新建 draft 规格，填写 SKU、适用艺人及销售策略。限量库存使用 `TRACKED`；无需提前备货、可重复售卖使用 `PROCURE_ON_DEMAND`；预售使用 `PREORDER` 并明确准备与送达时间。所有类型均由工作室在付款后准备并转交艺人。
3. 以英语编写源文案、规格名称、履约说明、预计送达范围和可选图文详情。选择拥有授权且处理完成的媒体。为全部七语言补齐译文；英语详情变动后重新翻译并独立审核。详情审核与基本文案审核分别完成。
4. 首次尚未发布的礼物，可先启用规格，再完成价格和内容的发布前检查。已有公开礼物新增规格时，应先在内容版本中补齐其七语言名称并发布，再启用该规格。
5. 从明确市场与币种的价格簿建立完整新版本，填写生效时间并发布。语言不决定市场或币种。`TRACKED` 规格需要真实可用余额，按单准备规格不创建虚构库存。
6. 执行内容预检、独立审核和发布，确认公开目录的价格、适用艺人与可售状态后启用礼物。当前发布、价格、库存与状态都参与最终可售判断。

## 调价与库存

价格版本复制服务端完整价格簿，只替换明确修改的规格金额；分页中看不到的其他价格仍保留。界面填写的新有效期应用于整本复制后的价格簿。首版只支持单一有效期来源，多有效期簿不允许直接复制；不能把一页价格当作整个簿。历史价格版本可作为明确来源，回退追加发布事件，作者版本号继续递增。

库存调整输入增减量及原因，系统在同一事务更新余额、追加流水和审计。运营不能修改预占量，减少后不得低于已预占数量。冲突时刷新并重新确认，不覆盖其他人的新修改。已被库存或交易历史引用的销售策略不能原位改变，改用新规格。

规格最多 64 个，适用艺人最多 2,000 个；后台提供艺人搜索与已选分页。价格及库存流水分页读取。无库存按单准备可以持续可售，但仍可通过暂停规格或礼物停止接单。

## 权限与历史兼容

商业读取、礼物管理、价格管理和库存管理分别授权。礼物类型属于 `gift.manage` 全局元数据；实际文案变更继续检查 `content.edit` 的对应语言范围，审核与发布沿已有独立权限。每次请求与重复请求都重新核实当前会话与权限。

旧版已发布礼物保留原有公开读取，可暂停或归档；从新后台恢复前，部分旧礼物需要复制内容、补充礼物类型并重新审核发布，以取得完整的新发布证明。新版本缺失礼物类型或发布证明时直接拒绝，不能冒充旧内容继续公开。

## 验证入口与范围

本地 Node/pnpm 版本以仓库配置为准。专项命令登记在 `packages/persistence-postgres/package.json` 与 `apps/api/package.json`，最终证据见 `docs/progress/phase-3-storefront.md` 的 P3-03 执行卡。

本阶段验证后台、真实 PostgreSQL、HTTP 与目录的可售结果。它不代表真实多次付款、PSP sandbox、正式身份服务、实际物品转交或生产发布已完成，这些沿后续阶段验收。
