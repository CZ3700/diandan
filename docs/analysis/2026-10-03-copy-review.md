# 上线文案审校（2026-10-03）

> 范围：商城界面文案（`packages/i18n/src/storefront`，7 语 × 352 键）、交易邮件（新模板版本 `notifications/v3`，3 事件 × 7 语）、后台界面文案（`packages/i18n/src/admin`，只纠正明确错误）。政策正文与关于/FAQ/客服页内容由 Mario 负责编辑上传，不在本范围。
> 目标两条：保障销售转化；规避站点责任与风险。冲突时风险优先。
> 流程：英文源文案分转化与责任两路审校 → 合并裁决 → 六语母语级本地化（同时复核其余全部键）→ 自动校验（ICU 解析、占位符一致、键集一致）→ 七语 390×844 / 1440×900 浏览器核对 → 所有者批准。

## 1. 主要改动

- **去掉不实或过度的承诺**：送达照片不再写“只有你能看到”（员工也能看），改为“不公开展示、仅供个人查看”；留言提示说明工作室会逐条审核，含联系方式或不良内容的留言可能不予转交，且永不公开；首页“由我们转交艺人”“不会向你寄送任何物品”；虚拟礼物说明“不含实物和直播鸣谢”；心愿展馆明确“公开”、提醒勿填个人信息、隐藏后不可恢复。
- **降低拒付与重复付款**：付款确认中、结果未知、订单待确认三处都加“请勿重复付款，确认后会发邮件”；结账页新增一行“礼物都是送给艺人的，不会寄给你；虚拟礼物付款确认即交付；不影响你依法享有的消费者权利”；付款方式处新增“在支付服务商的安全页面完成，我们不会看到或保存卡信息”。
- **付款后不再走进死路**：查单说明指向最近一封订单邮件、说明链接只能用一次、无效时联系客服并提供订单号；订单页新增客服与退款说明（取消、退款通过客服，批准的退款退回原付款方式，到账时间以银行为准）；付款成功页新增“确认邮件和查单链接正在发送，请查看垃圾邮件”。
- **术语统一**：gift bag / 礼物袋，region（不再对粉丝说 market），artist（不再说 recipient），Virtual gift（邮件与商城一致），secure order link。
- **邮件 v3**：付款确认邮件写明礼物是送给艺人的、不会寄给你；安全说明写明链接一次性、会过期、多封时用最新一封、失效或有疑问联系客服；PREPARING 邮件只陈述“已开始准备”，不承诺当前进度（邮件可能被晚读或重放）。v1、v2 原样保留供历史重放。
- **不写死品牌或邮箱**：遵守 AGENTS.md，文案只说“我们的客服”，不出现品牌名、域名、邮箱。

## 2. 随文案修正的显示问题（所有者 2026-10-03 批准）

- 虚拟礼物详情页显示虚拟礼物说明，不再显示与“付款即交付”矛盾的采购/预售提示和备货标签。
- 心愿展馆下拉框标签与其中一个选项同名 → 新增标签键（Show me as / 展示方式 等）。审校报告称公开名输入框 `maxLength=80` 与 40 字规则不符，经核实是有意设计（合同按 UTF-16 码元 80、字符 40），未改。
- 首页收尾按钮由“Artists”改为“认识全部艺人”；结账页付款语言回退提示显示语言名而不是原始代码（如 pt-BR）。
- 礼物袋里有不可售礼物且未锁定时，提示“请先移除不可选购的礼物”；后台旧工作区底部固定显示的“界面翻译尚待人工审核”一并删除。

## 3. 所有者决定

- 艺人关系为官方授权：不加“本站不是艺人官方服务”声明。
- 结账页不加未成年人提示。
- 审批记录按正式上线标准写入（APPROVED，审校人为所有者本人）。

## 4. 审校中发现、未在本轮处理的问题（建议后续评估）

1. 暂缓（ON_HOLD）订单在粉丝端显示为“准备中”（`packages/orders/src/fan-progress.ts`），迟到付款被暂缓、最终可能退款的订单也会显示“准备中”。
2. 虚拟礼物行付款即自动送达，其私密留言如何转交艺人没有定义；文案只写“审核后转交”，未承诺艺人会读到。
3. 后台留言审核只有通过/拒绝两个动作，“删改（REDACTED）”只是状态标签。
4. 后台没有下架心愿展馆公开记录的入口（已在审计 TXN-05 / 业务决定 6 中排期）。
5. 订单链接一次性、最长 7 天过期，粉丝无法自助重发；文案已如实引导到客服，根治需要“发送新链接”功能。
6. 生产 `siteName` 应配置为正式品牌，Stripe 账单描述符应与之一致，便于粉丝识别扣款。
7. 隐私政策若放在“我已阅读并同意”列表中，按 GDPR 类法规更宜作为告知链接（交 Mario 的政策配置时参考）。
8. 礼物袋、结账页、订单页的七语视觉核对需要完整后端，本机没有 S3 模拟，留到 stg 统一验收时补做；这些页面的新文案已有组件渲染测试覆盖。
